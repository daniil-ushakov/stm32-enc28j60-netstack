# Восстановление файлов протоколов

Файлы `ethernet`, `arp`, `ip`, `icmp`, `udp`, `net` реконструированы по обсуждениям проекта.
Исходные тексты этих модулей отсутствовали в репозитории. Это **не** гарантированно точные
оригиналы. Драйверы `enc28j60.c` и `enc28j60.h` не менялись.

Реализованы: Ethernet II; ARP Reply; IPv4 без фрагментации; ICMP Echo Reply;
UDP parsing/checksum; тестовый UDP-ответ для порта 33333 (`TEST` → `UFTU`);
`NET_SendUDP` с одним внешним кадром-буфером и `NET_ReceiveUDP`.

## Совместимость
- STM32F103 HAL, ENC28J60; вызов драйвера `ENC28J60_Init(mac, duplex)`.
- `NET_SendUDP(..., frame, capacity)` использует переданный `frame` как буфер
  Ethernet/IPv4/UDP; выделять ещё три буфера не требуется.
- Автоматический ответ на UDP по порту 33333 оставлен как прежний тест.
  Его следует отключить при переходе на собственный 40-байтный протокол.
- IPv4-фрагментация, IP options при передаче, ARP-кэш, маршрутизация,
  TCP, повторная передача, TTL и directed broadcast отсутствуют.
- Для отправки к узлу другой подсети нужен внешний механизм получения
  MAC-адреса шлюза/адресата (ARP-кэша нет).
- Приём поддерживает ограниченный broadcast 255.255.255.255.
- Аппаратная проверка STM32/ENC28J60 и сборка в IAR пока не проведены.
  Перед применением обязательно проверить совместимость сигнатур с локальным `main.c`.
